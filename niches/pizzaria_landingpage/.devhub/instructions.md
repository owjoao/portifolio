# Project Rules

- Use TypeScript with strict types.
- Use React 18+ and Tailwind CSS.
- Maintain dark premium aesthetic.
- Prioritize mobile performance and responsive layouts.
- Keep components modular and reusable.

## Google Flow Visual Assets
- For landing pages, marketing sites, online stores, portfolios, or requests that explicitly need generated images, use the verified images generated by the DevHub Maestro before wiring the page visuals.
- Before implementing visual sections (heroes, galleries, showcases, banners), consult `.devhub/artifacts/flow-images.json`. Use each verified image's `publicUrl` in frontend browser code (e.g. `/assets/generated/...`); preserve real workspace file paths (`public/assets/generated/...`) and include them in the task deliverables.
- If the user explicitly requested images and there are no verified images in `.devhub/artifacts/flow-images.json` for that request, forward the requirement to Maestro so it triggers the existing Google Flow scraper before concluding visual implementation.
- Respect the requested quantity (1–10). Do not generate images when the task does not need them, and avoid repeating generation if the manifest already contains verified PNGs on disk.
- Never invent URLs, placeholder services, or mock assets. Never substitute scraping failures with fabricated images, and never report visual tasks as completed without confirmed PNGs on disk.
- The DevHub main process owns the existing Google Flow scraper and persistent session. Do not recreate or modify scraping, selectors, CDP interactions, download logic, or session handling. Do not use OS mouse movement, do not open/focus the Flow window, and do not call renderer-only `window.devhub` APIs from the Antigravity CLI.
